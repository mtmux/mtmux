vs. tmate

tmate is the best tool in the world for "let me show you this for ten minutes." It forks a second tmux server and hands out an SSH or web link for a shared session.

mtmux is for your own sessions, continuously, from your own devices — with touch input and notifications. Different job: pairing versus commuting.

vs. ttyd & wetty

Both wrap a shell in a WebSocket and serve xterm.js. Excellent, minimal, and honest about scope: you bring the reverse proxy, the TLS, the auth, and the port.

mtmux dials out instead of listening, encrypts end-to-end past the relay, and adds the mobile input layer and agent watchers on top. If you already trust your own proxy and only need a desktop browser, ttyd is less machinery.

vs. mobile SSH clients

Native SSH apps are fast and mature, and some have genuinely good keyboards. The cost is a private key living on a phone, a reachable sshd, and no idea what happened while the app was closed.

mtmux pairs a revocable device key instead, needs nothing open, and pushes you when a run needs a decision. If you want a general-purpose shell to arbitrary hosts, keep the SSH app.

vs. VS Code Remote & code-server

If you want to write code on a tablet with a mouse, an editor in the browser beats a terminal. It's also a heavy install, a big attack surface, and a rough experience on a 6-inch screen.

mtmux doesn't try to be an IDE. It's the fastest path to the session your agents are already running in, on the device in your hand.

When not to use mtmux

›You need a shell on a host you don't control the daemon on — use SSH.
›You want a GUI editor with a file tree on an iPad — use VS Code Remote.
›You want to hand a colleague temporary write access to your terminal — use tmate.
›Your box has no outbound network access and no LAN reachability — nothing helps.

Everything else — a long agent run you want to keep an eye on from outside the house — is what mtmux was built for. Two-minute quickstart →
