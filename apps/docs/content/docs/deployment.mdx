## Two deployment models

There are two distinct topologies. Picking the wrong reverse-proxy wiring for
your model is the most common misconfiguration, so choose one and don't mix them:

- **CLI, single-port (recommended for a single machine)** — `tmuxremote start`.
  One Node process serves the web UI and the relay WebSocket on **one port**,
  with the WS exposed **same-origin at `/_relay`**. There is no separate relay
  port and you do **not** set `NEXT_PUBLIC_RELAY_URL`. Reverse-proxy setup is
  just: proxy everything to that one port with WebSocket upgrade headers. See
  [Getting Started](/docs/getting-started).
- **Split web + relay (this page)** — the web app and relay run as **separate
  services on separate ports** (web `14100`, relay `14300`). The browser reaches
  the relay via `NEXT_PUBLIC_RELAY_URL`, and the reverse proxy routes a
  dedicated **`/ws`** location to the relay. Use this for Docker/PM2 and
  multi-tenant deployments.

In short: `/_relay` with no `NEXT_PUBLIC_RELAY_URL` is CLI mode; `/ws` plus
`NEXT_PUBLIC_RELAY_URL` is the split model.

## Quickstart with `pnpm start:prod`

The fastest way to run tmuxremote's split model in production on a single host is the bundled
PM2 script. It builds, starts, and supervises all three apps on the
production port range (web `24100`, docs `24102`, relay `24300`) — distinct
from the dev range (`14xxx`) so dev and prod can coexist on the same host.

```bash
cp .env.example .env
# fill in AUTH_TOKEN, CORS_ORIGINS, NEXT_PUBLIC_RELAY_URL

pnpm install
pnpm start:prod      # build + pm2 start
pnpm logs:prod       # tail logs
pnpm restart:prod    # zero-downtime reload
pnpm stop:prod       # stop all apps
```

`pnpm start:prod` runs `pnpm build && pm2 start ecosystem.config.cjs`.
PM2 ships as a devDependency, so no global install is needed. The relay
refuses to boot in `NODE_ENV=production` if `AUTH_TOKEN` is empty / default,
or if `CORS_ORIGINS` contains a `localhost` origin — see
[Production Environment](#production-environment) below.

## Production Environment

Set these environment variables for production:

```bash
# === Relay ===
AUTH_TOKEN=your-secure-token-here       # openssl rand -hex 32
RELAY_HOST=0.0.0.0
RELAY_PORT=24300                        # dev: 14300 — prod: 24300
ALLOWED_PATHS=/home/deploy
CORS_ORIGINS=https://terminal.example.com
TMUX_DEFAULT_SHELL=/bin/bash

# === Web ===
NEXT_PUBLIC_RELAY_URL=wss://terminal.example.com/ws
WEB_PORT=24100                          # dev: 14100 — prod: 24100

# === Docs ===
DOCS_PORT=24102                         # dev: 14102 — prod: 24102
```

The relay server **exits on boot** if `NODE_ENV=production` and either
`AUTH_TOKEN` is empty / still the default sentinel
`change-me-in-production`, or any entry in `CORS_ORIGINS` starts with
`http://localhost`. See `.env.example` in the repo for the full
template with inline comments.

## Docker

Three services (`relay`, `web`, `docs`) are defined in
`docker-compose.prod.yml`:

```bash
docker compose -f docker-compose.prod.yml up -d
```

With the bundled nginx reverse proxy:

```bash
docker compose -f docker-compose.prod.yml --profile nginx up -d
```

The `--profile nginx` switch adds an `nginx:1.27-alpine` sidecar that
fronts web/relay/docs on ports 80 and 443.

### docker-compose.prod.yml (excerpt)

```yaml
services:
  relay:
    build: { context: ., dockerfile: docker/Dockerfile.relay }
    ports: ["${RELAY_PORT:-14300}:14300"]
    env_file: .env
    volumes: ["/tmp/tmux-1000:/tmp/tmux-1000"]
    healthcheck:
      test: ["CMD", "node", "-e", "…/health"]
    networks: [ccremote]

  web:
    build: { context: ., dockerfile: docker/Dockerfile.web }
    ports: ["${WEB_PORT:-14100}:14100"]
    depends_on: { relay: { condition: service_healthy } }
    healthcheck:
      test: ["CMD", "wget", "--spider", "-q", "http://localhost:14100"]

  docs:
    build: { context: ., dockerfile: docker/Dockerfile.docs }
    ports: ["${DOCS_PORT:-14102}:14102"]

  nginx:
    profiles: ["nginx"]
    image: nginx:1.27-alpine
    ports: ["80:80", "443:443"]
    volumes:
      - ./nginx/docker/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./nginx/docker/default.conf:/etc/nginx/conf.d/default.conf:ro
      - ./nginx/letsencrypt:/etc/letsencrypt:ro
```

## PM2

Use PM2 for process management without Docker:

```bash
pnpm build
pm2 start ecosystem.config.cjs
```

`ecosystem.config.cjs` defines three apps — `relay` (fork, 1 instance),
`web` (cluster, all cores), `docs` (fork, 1 instance) — each with log
files under `logs/`, `max_memory_restart` limits, and graceful shutdown
timeouts.

```js
// ecosystem.config.cjs (excerpt)
module.exports = {
  apps: [
    {
      name: "relay",
      script: "apps/relay/dist/index.js",
      exec_mode: "fork",
      max_memory_restart: "512M",
      wait_ready: true,
      kill_timeout: 10000,
      out_file: "./logs/relay-out.log",
      error_file: "./logs/relay-err.log",
      env_file: ".env",
    },
    {
      name: "web",
      script: "node_modules/.bin/next",
      args: "start --port 14100",
      cwd: "./apps/web",
      exec_mode: "cluster",
      instances: "max",
      max_memory_restart: "1G",
      out_file: "./logs/web-out.log",
      error_file: "./logs/web-err.log",
      env_file: ".env",
    },
    {
      name: "docs",
      script: "node_modules/.bin/next",
      args: "start --port 14102",
      cwd: "./apps/docs",
      exec_mode: "fork",
      max_memory_restart: "512M",
      out_file: "./logs/docs-out.log",
      error_file: "./logs/docs-err.log",
      env_file: ".env",
    },
  ],
};
```

Reload gracefully on deploy:

```bash
pnpm build && pm2 reload all
```

## Reverse Proxy

Two ready-to-use nginx configs ship in the repo under `nginx/`:

- `nginx/ccremote.conf.example` — for nginx installed on the host
- `nginx/docker/default.conf` — for the bundled docker sidecar

### nginx (standalone host)

Single-domain config with WebSocket upgrade, `/docs` subpath routing,
security headers, and HTTP → HTTPS redirect:

```nginx
server {
    listen 443 ssl;
    server_name ccremote.example.com;

    ssl_certificate /etc/letsencrypt/live/ccremote.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/ccremote.example.com/privkey.pem;

    add_header Strict-Transport-Security "max-age=31536000; includeSubDomains" always;
    add_header X-Frame-Options "SAMEORIGIN" always;
    add_header X-Content-Type-Options "nosniff" always;
    client_max_body_size 10M;

    location /ws {
        proxy_pass http://127.0.0.1:14300;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_read_timeout 3600s;
    }

    location /docs {
        proxy_pass http://127.0.0.1:14102;
    }

    location / {
        proxy_pass http://127.0.0.1:14100;
        proxy_set_header Host $host;
    }
}
```

### Key points

- The relay requires WebSocket upgrade (`Upgrade` / `Connection` headers).
- Set `proxy_read_timeout 3600s` (or longer) for long-lived sockets.
- Use `wss://` in `NEXT_PUBLIC_RELAY_URL` when TLS is terminated.
- Set `CORS_ORIGINS` to your production web origin.
