---
title: Running Claude Code Remotely
description: Watch and steer a long-running Claude Code session from your phone.
---

Claude Code runs in a terminal and does long things — refactors, test runs, whole
build pipelines. Being tied to the desk while it works is the problem mtmux
exists to solve.

Nothing here is a special integration. Claude Code is a terminal program, tmux
keeps terminal programs alive, and mtmux puts tmux in your browser.

## Setup

On the machine where Claude Code runs:

```bash
npm install -g mtmux
tmux new -s claude          # a session for it to live in
# start Claude Code inside that session
mtmux                       # in another terminal
```

Then get your phone on:

- **Same network** — scan the QR in the banner.
- **Anywhere else** — open `https://app.mtmux.com/pair`, read the code,
  and run `mtmux pair <code>` on the machine.

See [How pairing works](/docs/pairing).

## Why tmux and not just a terminal

The session outlives the connection. Close the tab on the train, reopen it at
home, and Claude Code is exactly where it was — still running, with its full
scrollback. Nothing is streamed to a third party and nothing is buffered
anywhere but your own machine.

## From the phone

- **Read the output.** Pinch to change font size; auto-zoom keeps the active
  pane readable after a split.
- **Answer it.** Approvals, corrections and follow-up prompts all go through the
  command bar, which is a proper text area rather than a single-line input
  fighting autocorrect.
- **Interrupt it.** `^C` is a fixed button on the keyboard toolbar.
- **Read what scrolled past.** Copy mode captures the pane and renders it
  read-only with Copy All.
- **Check the diff.** The file browser opens files in Monaco, and file watching
  means an edit made by Claude Code raises a reload banner instead of silently
  desynchronising your view.

See [Mobile](/docs/web-app/mobile).

## Practical settings

```bash
mtmux start --allowed-paths /home/me/projects
```

Narrow the file browser to the directories you actually want reachable. In the
split deployment, set `IDLE_TIMEOUT_MINUTES=0` if you want a connection to
survive hours of watching with no input — the default disconnects after 30
minutes of silence, and reconnection is automatic but re-attaches the terminal.

## Several machines

If Claude Code runs on more than one box, [an account](/docs/accounts) turns
"one code per machine" into one dashboard:

```bash
mtmux login
mtmux start --name "build box"
mtmux servers
```

Entirely optional. Anonymous pairing keeps working forever.

## What survives a dropped connection

| | Survives? |
| --- | --- |
| The tmux session and everything in it | yes |
| Terminal scrollback | yes, on the host |
| Your place in the session | yes — it re-attaches |
| Keystrokes typed while offline | **no** — deliberately dropped, never replayed |

That last row is a choice: replaying input into a session that has moved on is
worse than losing it.
