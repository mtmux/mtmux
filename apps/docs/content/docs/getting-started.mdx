# Getting Started

The fastest way to run tmuxremote is the published CLI. It bundles the web client
and the relay into a single process on one port, on the same machine as your tmux.

## Prerequisites

- **Node.js 22+**
- **tmux** installed and on your PATH (`brew install tmux` / `sudo apt install tmux`)

## Install

```bash
npm install -g tmuxremote
```

Any global installer works — `bun install -g tmuxremote` or `pnpm add -g tmuxremote`.

## Start

```bash
tmuxremote start
```

On start, the CLI:

1. Checks that Node 22+ and tmux are available.
2. Loads (or generates) a token at `~/.tmuxremote/config.json`.
3. Binds an HTTP server to `127.0.0.1:14100` that serves both the web UI and the
   relay WebSocket (same-origin, at `/_relay`).
4. Prints a banner with the URL and token, then opens your browser.

Enter the token when the page prompts you, then create or attach to a tmux
session. Press `Ctrl+C` to stop.

## Flags

```bash
tmuxremote start                       # bind 127.0.0.1:14100, auto-token, open browser
tmuxremote start --port 9000           # custom port  (-p)
tmuxremote start --host 0.0.0.0        # listen on all interfaces for LAN access  (-h)
tmuxremote start --no-open             # don't open the browser
tmuxremote start --token <value>       # one-shot token override for this run  (-t)
tmuxremote start --allowed-paths /home/me,/var/log   # file-browser allow-list
```

| Flag                      | Default     | Description                                          |
| ------------------------- | ----------- | ---------------------------------------------------- |
| `-p, --port <number>`     | `14100`     | HTTP + WebSocket port                                |
| `-h, --host <address>`    | `127.0.0.1` | Bind address (`0.0.0.0` to expose to the LAN)        |
| `-t, --token <value>`     | auto        | Override the auth token for this run                 |
| `--allowed-paths <paths>` | `$HOME`     | Comma-separated path allow-list for the file browser |
| `--no-open`               | —           | Don't open the browser on start                      |

## Managing the token

The token is stored at `~/.tmuxremote/config.json` (mode `0600`) and reused
across runs.

```bash
tmuxremote token print          # show the current token
tmuxremote token rotate         # generate a new token
tmuxremote token set <value>    # set the token to a specific value
tmuxremote version              # print version info  (alias: v)
```

## Accessing from another device

By default the server binds to `127.0.0.1` for safety. To reach it from other
devices on your network:

```bash
tmuxremote start --host 0.0.0.0
```

For internet access, put it behind a reverse proxy with TLS. The CLI is
**single-port**, so proxy everything to the one port with WebSocket upgrade
headers — there is no separate relay port and no `NEXT_PUBLIC_RELAY_URL` in CLI
mode. See [Self-Hosting](/docs/self-hosting) and [Security](/docs/security).

## Development (contributor setup)

To work on tmuxremote itself, run the monorepo in dev mode instead of the CLI.
This starts the web app and relay as **separate** processes (the split model),
which is a different topology from the single-port CLI above.

```bash
git clone https://github.com/GagnDeep/tmuxremote.git
cd tmuxremote
pnpm setup     # installs deps and creates .env from the template
pnpm dev
```

`pnpm dev` starts:

- **Web app** at `http://localhost:14100`
- **Relay server** at `ws://localhost:14300`
- **Docs** at `http://localhost:14102`

In dev the browser connects to the relay at `ws://localhost:14300` (set via
`NEXT_PUBLIC_RELAY_URL`), not same-origin `/_relay`. See
[Configuration](/docs/configuration) for all options and
[CONTRIBUTING.md](https://github.com/GagnDeep/tmuxremote/blob/main/CONTRIBUTING.md)
for the full workflow.
