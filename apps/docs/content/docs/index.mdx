## What is tmuxremote?

tmuxremote lets you access your server's terminal from any browser. It connects a
modern web UI to your tmux sessions over a WebSocket, giving you a full terminal
with session management, file browsing, and mobile support. It works great with
Claude Code, Vim, REPLs, and long-running jobs — anything you'd run in tmux.

The shipped product is the **`tmuxremote`** CLI, published on npm. One command
starts everything on a single port, on the same machine as your tmux.

## Install and run

```bash
npm install -g tmuxremote
tmuxremote start
```

That's it. The CLI generates a token, opens your browser, and connects you to
tmux on the same machine. No config file, no Docker, no reverse proxy required.

- **Requirements:** Node 22+ and `tmux` on your PATH.
- The server binds to `127.0.0.1:14100` by default.
- The auto-generated token lives at `~/.tmuxremote/config.json` (mode `0600`).

See [Getting Started](/docs/getting-started) for the full CLI walkthrough, flags,
and token management.

## Two ways to deploy

- **CLI (single-port)** — `tmuxremote start`. One Node process serves the web UI
  and the relay WebSocket (same-origin at `/_relay`) on one port. This is the
  primary, recommended path for single-machine self-hosting.
- **Split web + relay** — separate web (`14100`) and relay (`14300`) services for
  container/multi-tenant deployments, wired together with `NEXT_PUBLIC_RELAY_URL`
  and a `/ws` reverse-proxy route. See [Deployment](/docs/deployment) and
  [Self-Hosting](/docs/self-hosting).
